## 🔴 加时诊断：把"0/100"追到了**一行 SQL**

链路（全部本地实测）：

```
seed.sql  INSERT INTO "workbooks" ("name") VALUES ('Q3 Sales');   ← 正确
schema    CREATE TABLE "workbooks" (…, UNIQUE ("name"));           ← 有唯一约束
bootstrap 报告 0 错误；cells 进了 2 行；workbooks 始终 0 行
/api/workbooks -> 200 []                                          ← 判据因此找不到既有记录
```

**根因**：种子用 `INSERT OR IGNORE` 保证幂等，而 **`OR IGNORE` 会把 UNIQUE 冲突一起吞掉**；
`workbooks` 上恰好有 `UNIQUE ("name")` → 插入被静默忽略、表始终为空，
而日志/接口/前端**看不出任何异常**。

## 已落地的三处修复（都在包里）

1. **不再生成 UNIQUE 约束**（`schema_sql`）——这个约束的收益远小于它造成的静默失败；
2. **`seed.sql` 改成 `INSERT OR IGNORE`**（幂等）；
3. **启动后再断言一次种子**（`index.js` 监听成功后 1.5s 跑一次），兜住"启动早期竞态"；
4. 另外：**bootstrap 的失败语句现在会喊出来**（写 stdout + `.arc/db-bootstrap.json`）——
   今天这个 bug 之所以难查，正是因为它**完全静默**（逐条执行是必要的，但必须留声）。

实测佐证：`cells` 在两次种子运行后变成 **2 行**（说明再断言确实生效 ✓），
而 `workbooks` 一直是 0 行（说明被 UNIQUE 吞掉 ✓）——两条现象互相印证了这个诊断。
