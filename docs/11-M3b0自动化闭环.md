## 二、交付了什么（`pipeline/` 新增三个模块 + 一次接线）

| 文件 | 职责 |
|---|---|
| `pipeline/verify/l1.py` | **L1 静态闸门**：import 解析 / 路由与入口可达 / 声明的可访问名存在 / 数据库脚手架未被改 / npm scripts 完整 |
| `pipeline/verify/selfcheck.py` | **模型自检 + 定向修复**：需求原文 + L1 发现 + 代码全文 → 列违规（JSON）→ 按文件定向修 |
| `pipeline/verify/loop.py` | **闭环编排**：L1 → 自检 → 修复 → L1 复验，**有界轮次**（默认 3），每轮留痕 |
| `pipeline/main.py` | 接线：生成之后自动进闭环；`PIPELINE_VERIFY=0` 可关、`PIPELINE_REPAIR_ROUNDS` 调轮次 |

**为什么 L1 是静态的**：平台里 **agent 跑起来之后没有网络**（`docs/02` §一），`npm install` 做不了，
所以 agent 侧只能做**不需要依赖树**的检查；真正的 build/start 由平台做（V5 日志已证实）。
这一条决定了"构建是否成功"不能用"跑一次构建"来验，只能用**import 解析**这类等价但静态的判据。

## 三、闭环第一次跑**没有收敛**——四处缺陷与修法（都在实测中暴露）

第一版跑完，**held-out 判据不成立**：3 轮后仍有未解析的 import（`../lib/errors`），构建会失败。
四处缺陷逐个查清并修掉：

| # | 缺陷（实测现象） | 修法 |
|---|---|---|
| 1 | **L1 两个假阳性**：`/reference/register` 是需求里的**图片路径**（被我的正则当成页面路径）；`<Link to="/register">` 运行时会渲染成 `href`，静态只看 `href=` 会漏 | 先剥掉 markdown 资源语法再抽路径；`hrefs` 同时收 `<Link to=>` |
| 2 | **自检在被截断的文件上瞎猜**：文件截到 8000 字符，模型于是写"截断处未确认…可能缺失"，产出噪声违规 | 上限抬到 40000；prompt 明确"不要猜看不到的部分" |
| 3 | **第一次修复把 import 改错层级**（`../api/auth` → 又写错），**引入新的构建失败**（正是 M3a 5.1 那类） | 修复 prompt 显式要求"核对相对层级"；轮次 2 → 3，让被修坏的东西还有一轮机会 |
| 4 | 🔴 **模型爱 import 它自己没产出的辅助文件**（held-out 样本上连续出现 `./pages/LoginPage`、`../lib/errors`、`../../api/client`）→ 修复在"改 import 路径"和"下一个缺失 import"之间打地鼠 | **给修复步骤"已存在文件清单"**，并**允许它一并新建缺失文件**（只允许新建，不允许改别的既有文件） |

> **修 #4 之后 held-out 立刻收敛**：第 1 轮 L1 报缺 `LoginPage` → 修复**附带新建**它 → 第 2、3 轮 L1 全绿。
> 这条也是最"通用"的一条——它不是为某个样本打的补丁，而是补上了**模型生成的一个系统性弱点**。

**另外修掉的两个**（第一轮实测发现，属"我的检查器自己不对"）：
`check_routes_and_links` 把 `./reference/register.png` 当路径；`repair` 只接受同名文件回写。

## 六、诚实记下的局限（M3b-1 会撞上）

1. **自检会持续报"违规"，但最后一轮不修**（有界轮次的必然结果）。
   主跑结束时自检仍报 17 条，其中**有真有假**（例如它坚持"退出链接的可访问名必须是 `Sign out`"，
   而判据其实接受 `/退出登录|sign out/i`）。→ **L1 是客观闸门，自检是发现机制，不是闸门。**
2. **L1 抓不到语义**：能抓 import/路由/名字存在性，抓不到"行为对不对"。5.3 那类全靠自检。
3. **held-out 只验了"构建成功"**（判据就这么定的）。它的**通过率未知**——
   demo 自带 6 个 spec，可以顺手跑一下看能过几条，但那是 M3b-1 的事。
4. **每个样本都在 10 万 token 量级**，且自检阶段会**反复重发全文**（input token 占 60%）。
   → M3b-1 铺到 6 个任务前，必须先做 §7 M3b-1 的**模型/成本口径标定**。
5. **闭包依赖"它能看到的文件"**：修 #4 让模型可以新建文件，但也意味着**它可能造出多余的抽象层**
   （prompt 里已加"别为了图省事新建 lib/utils"，但这是软约束）。
