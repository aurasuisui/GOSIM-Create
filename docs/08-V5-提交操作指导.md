## 一、平台侧事实（本次打开页面核对，逐条可复查）

主赛道页面：**https://arc-bench.com/competitions/arc-bench-web**（Open for submissions）

**提交表单在右侧栏「Save an agent snapshot」，字段如下（括号内是实测默认值）：**

| 字段 | 默认值 | 说明 |
|---|---|---|
| 语言选择 | **Python 已选中**（`env-option active`） | 另两个是 JavaScript / TypeScript，**不要动** |
| 拖放区 | — | 文案：*Drop your agent code here. Keep the runtime entrypoint at the ZIP root.* |
| Submission name | 空 | 自己起个名 |
| Base URL | `https://api.arc-bench.com/v1` | 保留 |
| **API Key** | **空（Required）** | **要填我们自己的 key** —— 见下 |
| Model | `deepseek-v4-flash` | 保留 |
| Visual Model | `deepseek-v4-flash-vision-exp` | 保留 |
| Save submission 按钮 | **禁用** | 选好文件 + 必填项齐了才会亮 |

**三条对方案有影响的事实：**

1. 🔴 **平台要我们自己提供 API Key** —— 不是平台注入的。
   → token 消耗记在**我们交的这个 key** 上，`pass/CNY` 的分母就是我们 key 上的真实人民币消耗
   （这也解释了 `meter.arc-bench.com/user` 为什么"按 API key 查人民币消耗"）。
2. **`Model` / `Visual Model` 由提交时指定**，且这两个名字与工作区 `.env` 里的
   `MODEL` / `VISUAL_MODEL` **同名**。
   → 强烈暗示平台把它们（连同我们的 key）**当作环境变量注入 agent 进程**。
   → 若成立，**管线内部的分层模型路由仍然可行**（agent 自己拿 key 调网关），
     提交表单里的 Model 只是"面向平台记账的默认值"。**这一条要靠 V5 跑完看日志确认。**
3. **提交 = 一个快照 + 之后逐任务选跑**（表单原文：*This snapshot is shared by all competition tasks.
   Choose a task afterwards to run it.*）
   → 与"必须同一份提交跑完全部 6 个任务才计聚合分"一致。
   → **只跑 1 个任务不会产生聚合分，也不会污染榜单**（可以放心做 V5）。

## 二、提交步骤（照做即可）

**前置**：提交包已经构建并校验过（`./eval/package.sh` 全绿）：

```
C:\Users\aurasui\Desktop\Anything\GOSIM Create\output\bundle.zip
```

1. 浏览器打开 **https://arc-bench.com/competitions/arc-bench-web**
2. 右侧栏「**Save an agent snapshot**」区域，确认语言是 **Python**
3. 把 `output\bundle.zip` **拖进** "Drop your agent code here" 那个框
   （或点它打开文件选择器选那个 zip）
4. **Submission name** 填一个能认出来的名字，建议：
   - 第一次（本次验证）：`probe-v1-doctor`
5. **API Key** 填工作区 `.env` 里的 **`ARC_API_KEY`** 的值
   （已核对：`.env` 里 `ARC_API_KEY` / `OPENAI_API_KEY` / `api_key` 是**同一个 key**）
6. **Base URL / Model / Visual Model 不要动**（默认值就是我们要的）
7. 点 **Save submission**
8. 保存成功后再**挑一个任务跑**（建议 `Keep`——它最小，32 个模块/32 条测试；
   而且它的需求 YAML 是坏的，正好顺带验证我们的「输入修复壳」在平台上能不能修好）

## 三、提交后怎么核（已实测走通）

1. 浏览器打开 `https://arc-bench.com/competitions/arc-bench-web`（**需登录**；`History` 是会话/账号制的，
   填 API Key 不会显示历史——实测过）
2. 右侧栏 **History (N)** → 展开某次提交 → 每个任务一行 **Open run**
3. 进 run 页：先看 **Stage 1/2/3** 时间线（哪一步过了、哪一步没过），
   再看底部 **Stdout**（本例 2881 行，有 `Refresh logs`）
4. 同一页底部还有 **Download code**（下载该次提交产物）

**判读要点**：六任务同时报同一个错 → 问题在**公共环节**（如骨架、构建、起服务），
不要去翻某个 app 的需求。
