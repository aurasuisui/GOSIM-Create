## 三、⚠️ 已知瑕疵（第一版快照逻辑，已修）

Q2 / Q3 的 `load_snapshot` 记成了 `status=running；port=busy`。
**那不代表外部有测量在跑**——而是因为：拿锁之后**本序列自己**就成了"在跑"的那一方，
而第一版逻辑在第 2 轮起仍调用 `lock_verdict`，于是记下了自己。

- **正确读法**：Q2/Q3 的这两项是**自指的**，不代表污染；那两轮 `runners=0`，且序列期间无其他会话活动。
- **已在 13:5x 修**：`snap_world held` 分支——从第 2 轮起明确写 `status=self-held（本序列持锁中，看不到外部）`，
  只保留仍有意义的两项（runner 数、端口是否被外人占）。
- **未改原始记录**：三份 JSON 保持原样（它们是"工具当时确实这么写"的证据），解读以本文件为准。

## 四、由此得到的口径（已写进 `docs/04` §三 / §四 与 `AGENTS.md`）

1. **只在静置条件下比较**。`load_snapshot` 必须同时满足 `status=free`（或 `free-leftover`）与 `runners=0`；
   **含污染轮次的比较一律记为无效**，不要下结论。
2. **静置口径的噪声底线：失败数 0–2（跨度 2）** → 可辨差异下限 **2 条**。
3. **保留门槛 = 2 × 跨度 = 4 条**（静置条件下）。
   ⚠️ **N=3 偏薄**：静置样本目前只有 4 轮（含 R5）。**若后续静置轮次把跨度撑到 ≥3，门槛退回 6；≥4 则退回 8。**
   这条自我修正规则必须留着，否则一次薄样本会把门槛永久设错。
4. **每个 arm 都需要 `load_snapshot`**，否则那一轮无法参与比较——这是记录完整性的硬要求，不是可选项。
