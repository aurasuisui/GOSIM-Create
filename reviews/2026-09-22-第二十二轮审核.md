## 三、🔴 A. 那批"收紧"没提交，而 message 已经说它做完了

**证据（三方对照）**：

| 位置 | 内容 |
|---|---|
| `git show 6d2eaae:.githooks/prepare-commit-msg` | `grep -qF`（**子串**） |
| 工作区 `.githooks/prepare-commit-msg`（`M`） | `grep -qxF`（**整行**）+ 解释注释 |
| 工作区 `AGENTS.md`（`M`） | 审计查询已锚定 `^` + 写明"钩子侧用的是 `grep -qxF`" |
| `6d2eaae` 的 **message** | "已收紧为 `grep -qxF`…五个判据实测：…**只提及拒**…" |

**我做的判决演示**：同一份"只提及"消息
```bash
git show 6d2eaae:.githooks/prepare-commit-msg > /tmp/h.sh
ALLOW_FAST_COMMIT=1 bash /tmp/h.sh <只提及的消息> message    # → rc=0 放行   ⚠️
ALLOW_FAST_COMMIT=1 bash .githooks/prepare-commit-msg <同一份> message  # → rc=1 拒绝 ✔
```

**性质**：典型的"**amend 了 message、忘了 `git add`**"。范围是**两个文件**
（`.githooks/prepare-commit-msg`、`AGENTS.md`），且**工作区那份是正确的那份**。

**为什么必须收**：
1. **克隆/重装会拿到"松"的闸门**（`git config core.hooksPath .githooks` 之后生效的是提交版）——
   即"判据只在运行环境里是对的"，正是本项目最忌讳的形态。
2. message 是**审计线索**：它说"只提及拒"，而库里的版本做不到——**审计者会被 message 骗**。
3. 这条 commit 的正文本身就引用了两个词表值 → **它自己就是"提及被当成使用"的活样本**（它自己也写了这句教训）。

**修法（零风险、两条命令）**：
```bash
git add .githooks/prepare-commit-msg AGENTS.md
ALLOW_FAST_COMMIT=1 git commit --amend --no-edit      # 同轮 → 按它自己的纪律就该 amend
```
⚠️ **别用 `git add -A`**：工作区此刻有执行会话的 32 项在飞改动（见 §五）。
⚠️ amend 会改 `6d2eaae` 的哈希；若别处引用了这个哈希，要跟着改（目前只见于它自己）。
> 若判为"新的一轮"（规划会话已结束、由新一轮落地），则改用 `轮次: 独立-新轮次` 另起一条——**两种都可接受，但不要用裸标记**。
> 归属提示：`.githooks/` 不在三角色可写表里；它现在实际由**方案**维护（编码的正是 AGENTS.md 的纪律）——这条不构成违规，
> 但意味着"**谁改纪律谁改闸门**"，将来二者分家就是本轮这类 bug。
