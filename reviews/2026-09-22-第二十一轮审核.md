### B. 「守恒自检」是恒真式：**抓不到它自称要抓的失败，却会对合法 skip 误报**

```python

# ⇒ counted - total ≡ skipped  → 这个不等式只在 skipped>0 时才可能成立
```

我造的变异（同一份真实 judges 日志）：

| 输入 | 记录里的结果 | 守恒自检 |
|---|---|---|

## 四、🟡 建议处理

### C. `bench.sh` 仍在打印已作废的机制说明，且**方向不安全**

现场（锁**空闲**、3301 被占、3 个 runner）触发的结论行是：

```

   ⚠️ bench.sh 的常规子命令此刻都会被拒（锁 + 端口同时成立时的已知死锁）。
```

- **"锁 + 端口同时成立"不成立**：`status` 自己的证据块就写着"锁：空闲"。
- **"都会被拒"也是假的**：`acquire_lock()` 的拒绝分支**只在锁目录存在时**才进入；
  锁为空 → 直接放行 → `start/stop/reset/test` **都会执行**。
- `AGENTS.md` 已在 **2026-09-22** 明确作废过同一句话（"旧文写 port_busy → acquire_lock 永久拒绝 → 常规子命令全部不可用。**现在不是这样了**"）——
  **作废只落到了另一个分支**（`free-leftover` → 🟢），这句在 `ambiguous` 分支里活了下来。
- **不安全的方向**：读者若信"都会被拒"，就可能放心跑 `reset`（它**不会**被拒），
  而 `reset` 会接管端口、重置 DB → 复现 9/20 那次作废两轮的事故。

> **缓解事实（我核过，别过度报警）**：同一段里"不要跑 reset / stop"的**建议是对的**，而且
> `recover` 在"有 runner 活着"时**拒绝执行**（`--force` 也绕不过）→ 工具本身兜得住。
> 要改的是**文案**：把"都会被拒"换成真实条件（"锁为空 → 子命令会执行，**别跑**"）。

## 六之二、R3b 结论的强度边界（**下一轮复跑的判读口径**）

R3b 的读数差是 **1 通过 vs 0 通过 = 1 条**，而本项目自己定的**可辨差异下限是 2 条**
